# WhatsApp 聊天记录导入 CRM（已移除）

> 2026-10-30：用户已确认不再需要导出文件导入功能，系统入口和相关导入路由已移除。本文仅保留为历史说明。

> 零 API、零费用、不碰 WhatsApp 协议的方案：把手机导出的聊天记录解析后，按天写进客户跟进时间轴。
> **这是当前唯一无封号风险的 WhatsApp 接入方式**（内置会话因账号风控已停用，见 [whatsapp-risk.md](whatsapp-risk.md)）。

## 一、怎么用

**单个客户**：

1. 进入左侧 **客户增长 → WhatsApp**（或客户详情页右上角 **导入聊天**）。
2. 选客户 → 上传文件（或直接粘贴文本）→ **解析预览**。
3. 核对：消息数、覆盖日期、参与人、每天几条；日期顺序不对就切换「日期顺序」。
4. 点 **导入**。完成后跳到客户详情，跟进时间轴里出现 `WhatsApp 聊天记录 · 2026-10-15（32 条）`。

**批量**：同一页往下，「批量导入」一次选多个 `.txt/.zip`，按**文件名**自动找客户：

| 文件名 | 匹配方式 |
| --- | --- |
| `WhatsApp Chat with +971 50 123 4567.txt` | 号码（精确 → 联系人手机 → 后缀 9 位） |
| `WhatsApp Chat with Blue Ocean Trading.txt` | 公司名 / 英文名 / 联系人姓名 |

匹配到**唯一**客户才导入，匹配不上或撞号会跳过并在结果页说明原因。

**带媒体**：导出时选 **包含媒体 / With media**，安卓会给一个 zip（内含 `.txt` + 图片/语音/文件）。
这类 zip 直接传，附件会被存到 `uploads/wa-media/` 并挂到当天那条跟进记录的图片栏；
iOS 的 `<attached: xxx.jpg>` 和安卓的 `xxx.jpg (file attached)` 都能识别。

手机导出路径：聊天窗口 → ⋮（iOS 点客户名）→ 更多 → 导出聊天 → 选「带媒体 / 不带媒体」→ 得到 `.txt`（安卓是 `.zip`）。

## 二、支持的导出格式

| 行格式 | 来源 |
| --- | --- |
| `[2026/10/15, 09:12:33] Tom: 内容` | iOS / WhatsApp Web |
| `15/10/2026, 09:12 - Tom: 内容` | Android |
| `10/15/26, 9:12 AM - Tom: 内容` | 美式 12 小时制 |
| `[上午8:55, 2026/10/15] 客户: 内容` | 中文时段、时间在前 |
| `[2026/10/15, 09:12] Tom: 内容` | 老版本（无秒） |

细节：

- **戳里日期和时间的先后无关**，分别抠取；`上午/下午/凌晨/晚上` 与 `AM/PM` 都认。
- **日月顺序**：靠每行 >12 的那个数字判断；都 ≤12 时用全局默认（默认日先），可手动切换。
- **续行**自动并入上一条；`<Media omitted>` / `<媒体已省略>` 转成 `[图片]` 之类的占位。
- **系统提示**（加密说明、改群名等）不导入；空行、无法识别的行计入"无法识别行"。
- 单文件上限 12MB；文本按 UTF-8 解码，失败时回退 UTF-16LE / Latin-1。

## 三、幂等规则（重要）

唯一键是 **(客户, 会话指纹, 日期)**：

- 同一天重复导入 = **改写**那条跟进记录，不会出现两条；
- 下次导出更长的记录再导入时，重叠的日期被覆盖成最新内容，新增日期补一条；
- 会话指纹按"对方是谁"算（sha1），同一客户下不同号码/群不会互相覆盖。

**不会**写入 `next_follow_date`，所以导入历史记录不会影响逾期提醒和自动入池。

## 四、导入后怎么显示（重点）

客户详情页的跟进时间轴里，`type='WhatsApp'` 的记录不再是一坨灰字，而是：

1. **关键信息 chips**（自动从当天文本里抽）：金额（`3.2 USD`）、数量（`5000 pcs`）、贸易条款（`MOQ / FOB / PI`）、型号（`OW-500`）、日期。
2. **要点摘要（可选）**：点「生成要点摘要」，调用一次 DeepSeek，产出 1-2 句中文要点（客户要什么 / 我方答了什么 / 还差什么），存在 `wa_imports.summary`，**不覆盖原文**。没配置 Key 时不显示按钮。
3. **对话气泡**：我方靠右蓝色、客户靠左灰色，带发送人和时间。
4. **默认只显示最近 6 条**，更早的收在「展开更早的 N 条」里，避免刷屏。
5. 底部一行：`共 32 条 · 客户 24 条 / 我方 8 条`。

内容仍是纯文本存在 `activities.content`（可搜索、可导出、可被 AI 助理读），渲染时才结构化——所以**这次改动对已经导入的历史记录同样生效**，不用重导。

## 五、数据落点

| 表 | 内容 |
| --- | --- |
| `activities` | 每条 = 一天，`type='WhatsApp'`，正文为 `[10-15 09:12] 我方：…` 格式；当天有附件时 `images` 存图片路径数组 |
| `wa_imports` | 导入台账：客户、会话指纹、日期、activity_id、条数、内容哈希、来源、操作人、`summary`（AI 要点） |
| `uploads/wa-media/` | zip 里的图片/语音/文件（按内容 sha1 命名，重复导入自动去重） |
| `data/wa-tmp/` | 预览用的临时文本 + 媒体映射（48 小时后自动清理） |

> 注意：`uploads/wa-media/` 会随使用增长，建议每季度清理一次不再需要的附件（直接删目录里没人引用的文件即可）。

## 七、参考实现

开源项目 **GoodJob**（外贸 CRM，Apache-2.0）：<https://github.com/huangguojia/GoodJob>
其中 `whatsapp-plugin/src/server/services/whatsapp-history-import.ts` 与 `followup-sync.ts` 是同类需求的成熟做法，本项目借鉴了三点：

1. **戳内顺序无关的抠取**：先找时钟、再找日期，单独处理 `上午/下午`，避免 `2026/10/15` 被切成 `26/10/15`；
2. **按天幂等**：同一天重跑是改写（他们用 `priorActivityId` 回带，我们用 `(customer, chat, day)` 唯一键）；
3. **系统消息/空消息/撤回不进正文**。

没有照搬的部分：他们是独立服务（Express + React + MySQL + Socket.IO + 加密 AuthState + Meta/Baileys 双通道），
本项目是零构建的 Node 单进程，因此把能力收敛成"导入"这一件事。

## 八、已知限制

- 只导文字：媒体是占位符（导出时选"不带媒体"）。
- 不翻译：客户说西语/阿语时正文保持原文。下一步可接翻译（译文单独存，不覆盖原文——GoodJob 的做法）。
- 没有"内置会话"：收发仍需在 WhatsApp 里。要内置需接 Baileys（见 [whatsapp-feasibility.md](whatsapp-feasibility.md)），有封号风险。
