# WhatsApp 内置会话（Baileys）

> 左侧菜单 **WhatsApp → 会话**：扫码登录后进入三栏收件箱，可收发消息与附件、自动翻译、绑定/新建客户、快捷回复、AI 起草，并按天同步到客户跟进。
> 走的是 WhatsApp Web 的非官方协议（Baileys），**主号直连有封号风险**，这个前提你已知悉并接受。

## 一、首次使用

1. 确认本机有能出网的代理（Clash / V2Ray）。CRM 会自动读取 **Windows 系统代理**（本机实测 `127.0.0.1:7897`）。
   若系统代理没开，在页面「出网代理」里手填，如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:7891`，点「测试连通」。
2. 点 **扫码连接**，页面出现二维码。
3. 手机 WhatsApp → 设置 → **已关联的设备** → 关联设备 → 扫这个码。
4. 登录成功后状态变「已连接」，会话列表和历史消息开始同步。

退出登录会删掉本地登录态（`data/wa-auth/account-*`），再连要重新扫码。

## 二、功能

| 功能 | 说明 |
| --- | --- |
| 三栏收件箱 | 左侧会话、中间聊天、右侧客户与跟进，桌面和手机浏览器均可使用 |
| 筛选与搜索 | 全部 / 未读 / 待绑定 / 已绑定；按姓名、手机号、客户或消息内容搜索 |
| 未读提醒 | 实时客户消息累加未读，打开会话归零；侧栏显示未读角标 |
| 客户绑定 | 可按号码自动匹配，也可搜索客户手动绑定；未绑定会话可一键新建客户 |
| 聊天记录 | 文本、图片、视频、语音、文件；图片可灯箱预览，音视频可在页面播放 |
| 发送附件 | 支持从 CRM 上传图片/文件，单文件上限 20MB；附件和文字说明一起发送 |
| 快捷回复 | 每个账号维护自己的常用话术，一键填入输入框 |
| AI 回复草稿 | 自动判断客户语言，结合最近对话和 CRM 客户资料生成销售推进草稿；只填入输入框，不自动发送 |
| 自动翻译 | 客户文字消息可自动翻译成中文，原文与译文分开保存 |
| 跟进同步 | 已绑定会话可按天幂等写入客户跟进；重复同步只改写 WhatsApp 当天汇总，不删除手工记录 |
| 历史导入 | 已移除；系统只使用实时 WhatsApp 会话和手动同步跟进 |

## 三、隔离规则

- 每个业务员一个 WhatsApp 账号（`wa_accounts.user_id` 唯一），只能看到自己账号的会话。
- 客户按账号隔离；手机号自动匹配只会命中当前 WhatsApp 账号所属业务员的私有客户或公共池客户，不会误绑其他业务员的私有客户。
- 会话绑定客户后，只有会话账号本人可以发送；客户归属规则与 CRM 保持一致。
- 同步跟进时再次校验账号与客户归属，不一致会阻止写入。
- 公共客户池按共享规则可见；领取后客户回到领取人的客户管理。

## 四、翻译

翻译已改为谷歌翻译网页版使用的免费端点（`translate.googleapis.com/translate_a/single`，备用 `translate.google.com`），**不需要 API Key，不消耗 DeepSeek 额度**：

- 客户消息按需点「翻译」翻成简体中文；输入框可翻成英语、法语、阿拉伯语、西班牙语、俄语；
- 译文存在 `wa_messages.translated`，与原文分开存，可追溯；失败不会写入错误译文；
- 与 WhatsApp 共用同一套出网代理；免费端点可能被谷歌限流，界面会提示「限流，请稍后再试」；
- 机翻只作理解参考，数字、型号、价格和交期请对照原文核对。

## 五、踩过的坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 连接 408 握手超时 | 国内网络连不上 WhatsApp | 走代理（已支持系统代理自动识别） |
| 连接 428 Connection Terminated | `syncFullHistory: true` 在 Baileys 7.0.0-rc14 上会被服务器直接断开 | 已关掉；仍能收到最近一段历史，更早的用导出导入补 |
| 登录态半残导致反复重连 | 未完成的注册残留 | 连续 3 次失败就停下并提示重新扫码；必要时删 `data/wa-auth` |
| 页面显示“已连接”，但客户消息不进入 CRM | 旧版 Baileys 初始化超时；或本地 Signal 会话/预密钥缓存损坏，表现为 `Invalid PreKey ID`、`No session found to decrypt message` | 先升级协议层；再暂停连接、归档 `session-*.json` 并重连。仍出现“在线但接收异常”时，用“退出登录并修复”重新扫码，不要连续点重连 |
| 手机反复弹出“已完成与 Chrome 上的 WhatsApp Business 同步” | 每次强制重连都会被手机当作一次设备登录事件；反复重连还会增加风控风险 | 在线状态不再提供“重新连接”按钮。排障时最多重连一次；仍异常则重新扫码 |
| 离线补发的客户消息没有未读角标 | 旧逻辑只把 `messages.upsert(type=notify)` 计为未读，`type=append` 被漏掉 | 已把 `append` 的真实客户消息也计入未读和跟进同步 |

### 接收健康检查

`GET /api/wa/health` 会返回：

- `receiveState`：`offline` / `waiting` / `receiving` / `degraded`
- `decryptFailures`：本次连接中，非状态消息的加密解密失败数量
- `notifyEvents` / `appendEvents`：实时事件与离线补发事件数量
- `lastInboundAt`：最近一条成功进入 CRM 的客户消息时间

`receiveState=degraded` 表示 WebSocket 虽然在线，但消息正文无法解密；此时重复重连没有意义，应重新扫码修复关联设备。
