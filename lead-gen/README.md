# 获客核验系统（lead-gen）

独立运行的线索核验系统，**不改动主 CRM 任何代码**。导入线索名单后，从多个公开来源交叉验证行业、规模、社媒和联系方式，生成带置信度、联系推荐分和完整证据链的画像报告；再经人工审批，把候选线索变成「可联系」线索。获客闭环借鉴了 GoodJob CRM 的思路，但未复制其代码。

## 启动

```bash
cd D:/外贸CRM/lead-gen
node server.js
```

浏览器打开 `http://localhost:5101`（独立端口，不影响主系统的 5000）。

- 独立数据库：`lead-gen/data/leads.db`（不会碰主系统 `data/crm.db`）
- 零安装：只用 Node 22 内置模块；Excel 导出复用主系统 `node_modules/exceljs`

## 使用流程

1. **导入线索**：`/import` 粘贴 CSV 或从 Excel 复制（Tab 分隔）。按域名或公司名自动去重，新线索进入「候选池」。
2. **核验**：在线索库点「核验」，或到「核验任务」批量核验。后台队列逐条采集+验证。
3. **查看画像**：看字段级结论（已确认/证据弱/冲突/缺失）、置信度、邮箱/电话、可展开的证据链（来源+原文+URL），以及可解释的「联系推荐分」。
4. **人工审批**：推荐分达标且无冲突的候选可一键勾选；最终必须由人工点「审批通过」才进入「可联系」状态，驳回/退回均可追溯。
5. **导出报告**：导出全部、已审批或选中线索，Excel 含线索总览 / 字段验证明细 / 证据链三个 sheet。

## 验证方法（多源交叉）

| 字段 | 来源与做法 |
|---|---|
| 行业 | 官网 JSON-LD `industry` + OpenGraph/meta 描述 + 搜索摘要，中英文关键词映射到标准行业分类，多源投票 |
| 规模 | JSON-LD `numberOfEmployees` + 描述文本里的员工数（支持 `51-200 employees`、`over 1000` 等），归一到标准档位 |
| 国家 | 地址字段 + 国家关键词 + 域名 ccTLD |
| 官网 | 输入网址直连抓取，验证可达性与元数据 |
| 社媒 | 从官网 HTML 提取 LinkedIn/Facebook/Instagram/YouTube/X 官方外链（比爬平台可靠） |
| 成立年份 | JSON-LD `foundingDate` + 描述文本年份 |
| 邮箱/电话 | 只从官网与社媒证据文本中用正则抽取，多值并列；不猜测、不做可达验证 |

每个字段：多来源一致 → 已确认；单来源/弱证据 → 证据弱；多值互斥 → 冲突；无证据 → 缺失（留空，不编造）。

**可信分** = 行业 24% + 规模 22% + 社媒 18% + 官网 12% + 国家 9% + 成立年份 5% + 粉丝数 5%（描述仅作佐证，不参与打分）。

**联系推荐分（1.2.0 新增，借鉴 GoodJob）** = 基础可信度（可信分 × 0.7，最多 70）+ 联系方式（邮箱 +12、电话 +8）+ 多源佐证（来源数/已确认字段数，最多 +10）− 冲突扣分（每个 -10，最多 -20）。详情页会列出每一项得分原因。推荐分只给建议，**不会自动把候选变成可联系线索**。

## 数据源设置

`/settings` 可配置：
- **社媒直读（默认开启）**：走本地代理（默认 `http://127.0.0.1:7897`）+ r.jina.ai 文本阅读器，读取 LinkedIn / Facebook 公开主页，拿到**员工规模、行业、粉丝数、地址、邮箱**等硬指标
- **官网通道**：JSON-LD / OpenGraph 元数据 + 社媒外链，开箱即用
- **增强通道（可选）**：填入 Google Custom Search API Key/CX 或 SerpAPI Key 后自动启用
- 请求间隔、超时、结果数可调（默认间隔 1200ms，避免触发反爬）
- **采集通道开关**：可勾选 website / bing / 各社媒搜索 / Google CSE / SerpAPI；未勾选的通道不发起请求，未配置 Key 的源自动跳过
- **人工审批建议阈值**：默认推荐分 70，达到且无冲突才会出现在「一键勾选」候选中（仍须人工确认）

## 当前网络环境适配说明（2026-11-20 实测）

| 通道 | 状态 | 获取的数据 |
|---|---|---|
| 公司官网直连 | ✓ 可用 | 行业、规模、成立年份、联系方式（JSON-LD） |
| LinkedIn 主页（经 7897 代理 + 阅读器） | ✓ 可用 | **Company size（员工数）**、Industry、粉丝数、总部、成立年份 |
| Facebook 主页（经代理 + 阅读器） | ✓ 可用 | 类别（Industrial Company 等）、简介、粉丝数、地址、电话、邮箱 |
| Instagram | ✗ 登录墙 | 只能从官网外链确认存在性 |
| Google 搜索 | 需 API Key | 配置 CSE/SerpAPI Key 后启用 |
| Bing 搜索 | 受限 | 结果本地化污染，已做公司名相关性过滤 |

**代理说明**：社媒/搜索需走代理，设置页 `proxy_url` 默认填 `http://127.0.0.1:7897`（本机实测可用）。留空则不走代理。若你的代理端口不同，请到设置页修改。

示例效果：以一家虚构的门五金企业为例，接入社媒直读后可信分从 53 提升到 **81（A级）**，并识别出规模、粉丝数与成立年份。真实来源分歧（如成立年份）会显式标记为冲突，交由人工复核。
