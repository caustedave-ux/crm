# 外贸客户自动回复工作台 v2.2

针对 **Facebook 投流询盘**设计：客户来源不精准，所以**先判定客户是否精准**（是否从中国采购过），确认精准后才发画册/报价/现货图。独立运行，不改动主系统任何代码。

---

## v2.0 核心变化

v1 是"有消息就回"，v2 变成"先筛选再跟进"：

```
新消息 → v1安全闸门 → AI判定(语言/目的/精准度)
                          ├─ 精准 → 按目的发素材(画册/报价/现货图)
                          ├─ 信息不足 → 追问1个qualify问题(最多2轮)
                          └─ 不精准 → 放弃，不纠缠
```

**判定状态跨消息保存**：一个客户判过一次就记住；同一目的素材 7 天内不重复发送。追问满 3 轮仍不明 → 转人工。

自动回复采用自然 WhatsApp 销售口吻，不使用编号列表或“为了准确报价请确认以下内容”等模板句式；每轮只追问一个最关键的信息，并优先复用已知广告产品、国家和聊天内容。

**页面总开关**：登录 CRM → WhatsApp 页面 → “自动回复总开关”。开启时自动写入当前登录会话并启动后台 worker；关闭时立即停止 worker。只有管理员可以操作。

## 可靠性状态（重要）

**当前建议：保持 `enabled=false`，只做观察和人工审核，不要直接开启无人值守发送。**

- 51 项逻辑自测通过，但自测只验证状态机和防护，不等于 AI 判定准确率。
- DeepSeek 网络失败会最多重试 3 次（1.5 秒、3 秒退避）；仍失败才记录错误。
- 使用 12 个真实 WhatsApp 对话做离线抽样后发现，旧 v2.0 至少存在“老客户误判不精准”“投诉客户误判精准”等明显风险。
- v2.1 已修复高风险自动发送、重复发素材、客户档案/收款上下文缺失等问题，但样本中仍有真实客户被保守判为 unknown。
- 正式启用前建议至少人工标注 50-100 个真实询盘，确认误放行率、误放弃率和人工复核率，再决定是否开放自动发送。

## 精准度怎么判（AI）

核心标准：**客户是否曾从中国公司采购过、是否有真实进口采购能力**。

- **精准 high（置信度≥0.82）**：已有 CRM 成交/收款/有效 PI/历史报价且有新需求；或采购意图明确，并且具体产品、数量、目的国、贸易条款、交期认证、中国采购经验中至少满足两项。
- **不精准 low**：只有高置信度且出现明确排除证据时才允许放弃，例如求职、同行套价、代理拉客、垃圾信息、明确没有采购需求。
- **信息不足 unknown**：只有问候、只有价格没有产品、只有“想买”但没有型号/数量/市场、第一次进口但信息太少。系统会先追问，不会直接放弃。追问会复用已知的广告产品、客户国家和身份，不再重复询问已有信息，并优先补齐型号、箱数和中国采购经验。
- **高风险 hold**：投诉、质量争议、退款、律师、付款争议等一律转人工，不调用自动发送。

“是否从中国采购过”是加分项，不是必要条件；第一次进口但需求具体的真实进口商也可以判 high。

系统还会做一次确定性校验：如果客户采购意图明确，并同时具备具体产品、数量、目的国、贸易条款、中国采购经验中的三个强信号，即使 AI 初判 unknown，也会纠正为高精准。投诉、退款、律师、付款争议等风险仍会强制转人工。

追问问题由 AI 用**客户自己的语言**生成（英语客户用英语、法语用法语……），例如问"您需要什么产品？目前是否从中国采购？"

## 素材准备（重要）

系统里**没有现成的画册文件**，所以画册需要你提供：

| 目的 | 素材来源 | 放哪 |
|---|---|---|
| 画册 catalog | 你提供的 PDF/图片 | `materials/` 目录，如 `materials/catalog.pdf` |
| 报价 quote | 你提供的报价文件 | `materials/quote.pdf`（没有则发提示"稍后给正式报价"） |
| 现货 stock | `materials/stock/` 中优先 PDF；无 PDF 时回退图片 | 目录中有 PDF 时默认发送全部 PDF，没有 PDF 才发送全部现货图片 |

**操作步骤**：把画册文件（PDF 或图片）复制进 `auto-reply/materials/` 即可。脚本会自动找这个目录里第一个 PDF/图片当画册。现货图默认从产品库取，不用额外准备。

> 素材目录已建好：`materials/` 放画册/报价，`materials/stock/` 放现货图（可选）。

## 三步启动

**第 1 步：登录 CRM** — 打开 WhatsApp 页面，使用页面中的“自动回复总开关”即可，不再需要手工复制 cookie。

**第 2 步：放素材 + 观察（强烈建议）**
把画册文件放进 `materials/`，保持 `"enabled": false`，双击 `start.bat`。
此时**不发真消息**，日志会记录 AI 的判定（精准度/目的/依据）和"本该发什么"。观察几天，确认判定准、素材对。

**第 3 步：开启自动发送**
在 WhatsApp 页面点击“开启自动回复”。后台 worker 会自动启动，并使用当前管理员会话发送。

> 随时改回 `false` 重启即停。这是总闸。

## 安全刹车（全部内置）

| 刹车 | 默认 | 作用 |
|---|---|---|
| 置顶跳过 | 开 | 置顶客户一律不回（你的核心要求） |
| 人工优先 | 开 | 最后一条是我方发的 → 不回，不抢话 |
| 观察模式 | 开 | `enabled=false` 只记不发 |
| 资格判定 | 开 | 不精准不发素材，先筛选 |
| 追问上限 | 3 轮 | 每轮只问一个关键点，优先产品、数量、中国采购经验，避免连环盘问 |
| 已精准记忆 | 开 | 判过一次不再重判；同一类素材 7 天内不重复发送 |
| 风险词硬拦截 | 开 | 投诉、退款、律师、付款争议直接转人工 |
| 置信度门槛 | 开 | high 最低 0.82，low 自动放弃最低 0.85 且有明确排除证据 |
| CRM 强证据 | 开 | 读取客户档案、历史报价、有效 PI、收款记录和广告来源 |
| 置顶三重拦截 | 开 | 判定前跳过、发送前再次检查、已置顶客户永不自动回复 |
| 发送前二次确认 | 开 | 生成期间被置顶/人工回复则放弃，防竞态 |
| 现货 PDF 优先 | 开 | `stockPreferPdf=true`，现货目录有 PDF 时只发 PDF；无 PDF 才回退图片 |
| 现货全部发送 | 开 | `maxStockImages=0`，选中的现货 PDF 或图片全部发送并逐张限速 |
| 冷却窗口 | 10 分钟 | 同一客户两次自动动作的最小间隔 |
| 每日自动批次 | 150 次 | 支持约 100 个询盘并预留追问/重试空间 |
| 每日覆盖客户 | 120 个 | 按 WhatsApp 会话去重，同一客户不重复占新客户额度 |
| 每日素材包 | 20 个 | 防止大量客户同时触发全套现货图 |
| 每日文件数 | 300 个 | 超过后高意向客户转人工，降低 WhatsApp 风控 |
| 群聊跳过 | 开 | 只处理一对一会话 |
| 首次保护 | 开 | 只回启动后的新消息，不补发历史 |

## 查看日志

- 文本日志：`auto-reply.log`
- 结构化日志：`state.db`
  - `qualification` 表：每个客户的判定状态（精准度/目的/依据/追问轮数）
  - `sent_log` 表：`action` = `dry`观察 / `sent`已发 / `qualify_ask`追问 / `unqualified`放弃 / `hold`转人工 / `skip`跳过 / `error`失败

常用查询：
```sql
-- 今日各类动作统计
SELECT action, reason, COUNT(*) n FROM sent_log WHERE substr(at,1,10)=date('now') GROUP BY action;
-- 判定为精准的客户
SELECT * FROM qualification WHERE status='qualified';
-- 需要人工处理的
SELECT * FROM sent_log WHERE action='hold' ORDER BY id DESC;
```

## 常见问题

**Q：日志显示"资格判定失败：主系统未配置 DeepSeek API Key"？**
A：去 CRM 的"系统设置 → AI 助理"配上 DeepSeek Key。v2 的判定直接复用这个 Key，不额外配置。

**Q：判定都成了 unknown（信息不足）？**
A：FB 投流客户第一句常是"hi"——这正常，AI 会追问。可在 `qualify.js` 的 SYSTEM_PROMPT 里调整判定规则。

**Q：判定精准但没发素材？**
A：检查 `materials/` 里有没有画册文件。`send_log` 的 `reason` 会写"判定精准但 materials 目录没有可用素材"。

**Q：会不会重复发送/重复追问？**
A：不会。按 `wa_messages.id` 游标 + `qualification` 状态双重记账，重启、重连都不回头。

**Q：想退回 v1 简单模式？**
A：`config.json` 里把 `qualify.enabled` 改成 `false`。
